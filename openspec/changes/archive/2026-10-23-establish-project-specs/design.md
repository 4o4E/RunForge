## Context

RunForge 已有系统、空间、插件、多模态和隔离说明，但缺少可验证的 OpenSpec 行为基线。4o4E/skills 原始开发流程包含规格发布、术语与架构决定维护，需要适配本项目已有工作方式。

## Goals / Non-Goals

- 目标：一个规格来源、一处架构决定记录，开发技能能够实际读取和更新这些内容。
- 非目标：修改产品运行时、重写其他会话的未提交代码、发布应用、执行数据库迁移或改造共享环境。

## Decisions

### 2026-10-23 — OpenSpec 统一规格与架构决定

- 状态：accepted，用户在本次会话明确要求。
- 背景：用户选择将 4o4E/skills 接入 RunForge，并明确技能中的 ADR 相关内容应由 OpenSpec 覆盖。
- 决定：现行行为位于 `openspec/specs`；变更范围、架构决定和任务分别位于同一 change 的 proposal、design 和 tasks；完成后归档。领域术语独立保存于 `GLOSSARY.md`。
- 原因：架构选择与相关需求、实施和证据一起保存，避免技能创建独立且可能冲突的规格或决定记录。
- 备选方案：保留独立 ADR 并由 OpenSpec 引用同样可以工作，但会产生两处更新与跨文档状态维护；用户选择由 OpenSpec 统一承担。
- 后果：项目内的 domain-modeling、to-spec、实现和审查流程使用 OpenSpec；技能上游更新需要复核这些项目适配。GitHub Issues 只跟踪工作项并引用规格。

### 2026-10-23 — 项目级技能采用可编辑文件

- 状态：accepted，按用户选择的项目接入范围实施。
- 决定：安装 4o4E/skills 正式工程与生产力技能至 `.agents/skills`，保存来源锁；官方 OpenSpec 同样生成共享目录技能。使用项目副本，不安装全局插件。
- 原因：用户要求项目级接入，且本项目需要修改规格与决定读写流程；可编辑文件可以随项目评审，不影响其他仓库。
- 后果：更新不是自动操作。来源锁记录上游来源内容，不冒充已适配文件的字节校验；更新时必须保留并复核项目规则。

## Imported Decisions

以下条目来自原本机已确认记录与现行专题，保留原时间和关系。它们解释既有实现，不表示本次重新实施或验收产品功能。

### 2026-10-17 23:27:06 UTC+8 — 外部共享对话管理权限

- 状态：accepted，既有用户确认。
- 背景：external 对话由调用方创建，同一空间的多个用户共享查看，归档和删除会影响其他查看者。
- 决定：仅租户 owner/admin 可以置顶、重命名、归档、恢复和永久删除；普通可见成员只读。消息、文件、分支和执行不因管理权限开放写入。
- 原因：用户在仅租户管理员与所有可见用户之间选择前者，避免普通成员删除共享任务；删除复用已有归档和运行停止约束，并清理会话工作目录。
- 对应规格：`spaces-external`。

### 2026-10-19 17:59:04 UTC+8 — 图片理解与只读资源

- 状态：图片理解部分 accepted；资源权限部分由下文 21:53:27 决定替代。
- 背景：长截图输入拒绝被误判为无视觉能力；对完整 Shell 命令的字符串检查误拒正常工作区操作。
- 决定：图片使用多模态分析；超出输入尺寸限制时明确要求裁剪或缩放，不自动安装 OCR 或损失图片内容。资源保护由真实文件边界与操作系统只读挂载承担。
- 原因：输入错误应指向具体图片，不能借此改变模型真实能力或依赖模型遵守命令文字限制。
- 对应规格：`files-multimodal`、`tools-shell`。

### 2026-10-19 19:17:37 UTC+8 — Linux Shell 始终保护资源

- 状态：隔离范围部分 accepted；实体资源权限部分由下文 21:53:27 决定替代。
- 背景：原容器范围执行可以绕过 bwrap，单凭源文件权限不能保证资源只读；强制完整会话隔离又会改变容器目录可见范围。
- 决定：所有 Linux Shell 都经过 bwrap，保留容器范围与完整会话隔离两种选择；bwrap 缺失或不可用时明确失败。非 Linux 范围不扩展。
- 原因：用户选择始终保护资源、隔离范围可选，而不是始终完整隔离。
- 对应规格：`tools-shell`。

### 2026-10-19 21:53:27 UTC+8 — Shell 资源仅使用只读挂载

- 状态：accepted，替代上述两个条目中实体副本移除写位及清理恢复权限的部分。
- 背景：逻辑入口与真实资源目标均已由 bwrap 只读挂载，用户选择保留原文件权限。
- 决定：Shell 资源只读由 bwrap 挂载提供，物化保留原权限；服务端直接清理目录或链接，不移除写位或恢复权限。文件工具继续执行身份、真实路径与运行选中资源授权。
- 原因：Shell 与文件工具分别承担其边界，源文件权限不再承担 Shell 隔离职责；插件历史锁与隔离范围不变。
- 对应规格：`tools-shell`、`skills-mcp`。

## Risks / Trade-offs

- 文档与开发技能容易在上游更新时恢复默认约定：更新后检查所有实际决定和规格读写入口，而不只修改配置说明。
- 已有未提交代码不等于稳定版：基线描述当前源码，发布和实例状态另行确认。
- OpenSpec 静态校验不验证产品行为：本次只验收文档和技能入口，不冒充应用端到端验收。

## Migration Plan

导入既有产品行为作为主规格；本次新增的开发工作流通过 change delta 同步。原本机术语和决定入口改为引用正式位置，不再维护重复正文。运行数据、配置、数据库和部署方式保持不变。
