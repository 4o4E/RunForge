---
name: video-analysis
description: 转写 B 站视频并结合分区、简介和重点评论分档处理；知识分析视频才读取画面和核验事实。
---

目标：在视频信息卡已经发送后，先取得实际语音和重点评论，再判断是否需要额外回复。标题、分区和简介已经说明内容时静默结束；信息不足时给出简短概述；只有包含大量知识讲解、论证、推导或系统分析的视频才做详细分析。分析必须客观区分视频作者内容与评论观点，忽略插播广告、求关注和无关闲聊。B 站插件负责平台链接、媒体、元数据和评论；通用音视频插件负责转写和媒体处理。禁止插件自行调用语言模型；Agent 直接阅读材料并组织结果。

当前 shell 工作目录是会话工作目录。以下 `<root>` 指其中的 `plugins/bilibili-video-analysis/skills/video-analysis`，媒体文件也写在当前工作目录；执行脚本时保持这个工作目录。

1. 先运行 `node <root>/scripts/video.mjs metadata <URL> <工作目录>`，只获取目标分 P 的元数据。
2. 不在元数据阶段结束任务。运行 `node <root>/scripts/video.mjs audio <URL> <工作目录>` 下载实际音轨。调用 `skill_activate` 激活 `business:audio-video-tools/audio-video-tools`，记住激活结果中的通用音视频 Skill 根目录，再按其说明运行通用转写脚本，把结果写到 `<工作目录>/<BV号>-p<分P号>-transcript.srt`，并用 `file_read` 读取。转写为空也是有效结果，仍继续读取评论，再结合元数据判断是否静默结束；不要用画面识字补写没有语音的内容。
3. 运行 `node <root>/scripts/video.mjs comments <URL> <工作目录>`，并用 `file_read` 读取生成的评论文件。脚本会优先保留 UP 主置顶、其他置顶和高赞评论。评论接口失败时直接继续，不重复请求，不影响视频主体分析。此时已经读取元数据、转写和重点评论，除此之外不得下载视频、抽取关键帧或搜索外部资料。
4. 根据分区、标题、分 P 标题、简介、实际转写和重点评论选择一次处理档位：
   - `none`：信息卡已经足以说明视频是什么，转写和评论没有带来值得另行说明的内容。已经明确作品名和集数的动画、影视正片、歌曲、舞蹈、综艺、游戏实况、整活、剧情或表演内容必须属于此档；转写很长、涉及心理或社会主题、评论讨论剧情，都不能把这类内容升级为详细分析。直接输出跳过结构，不再调用工具。
   - `brief`：标题和简介无法说明实际内容，但转写能让用户知道视频讲了什么。用几句文字概括内容；重点评论确有信息价值时在 `audienceResponse` 中简短说明。此处只概括明确归属于评论的观众反应或观点，不把未经核验的评论事实说法写成结论。选择后不得再调用任何工具。
   - `detailed`：必须同时满足三个条件：视频的主要目的在讲解现实知识、方法、因果关系或可验证结论；转写中存在持续的说明、论证、推导或证据链；核验核心主张能够避免读者被误导。叙事对白、剧情发展、角色心理、表演、作品欣赏和娱乐讨论不属于知识分析。分区只是参考，不能仅因处于知识分区就选择此档。只有满足全部条件才继续执行后续步骤。
   - 转写语言不符、断句粗糙、识别不完整或内容难以理解，都不能作为下载视频、读取画面或搜索资料的理由。元信息已明确作品或内容类型时选择 `none`；元信息含糊时最多选择 `brief`，并依据现有转写如实保留不确定性。不得为了判断档位而读取画面或搜索。
5. 详细档中，只有图表、演示、屏幕文字或现场证据影响论证时，才运行 `node <root>/scripts/video.mjs video <URL> <工作目录>` 下载视频，再按通用音视频 Skill 的说明执行 `frames.mjs`。只抽取与核心论证直接相关的少量画面，读取后停止，不为复述剧情、识别人名或增加细节而逐帧查看。
6. 视频作者和评论里的事实主张使用相同核验标准。只处理会影响核心结论、属于非常识且可客观验证的主张；仅在存在争议、会显著影响判断或明显可能误导时搜索独立来源。一般事实、次要细节、普通感想和单纯观点不搜索。外部证据支持原说法时不生成 `factChecks`；只有错误、片面、证据不足或仍无法确认时才写入，`claim` 明确说明主张来自视频还是评论。找不到可靠来源时使用 `uncertain`，不继续扩大搜索。
7. 只有非领域读者缺少必要前置知识、无法理解视频核心论证时，才搜索延伸资料。每条 `extensions` 必须有实际查询到的独立来源；没有必要内容时使用空数组。不要扩展主讲者背景、主页、其他作品或泛泛推荐。`videoContent.overview` 精简说明主题与结论，`segments` 按时间讲清核心论证、证据、例子和条件。`spokenExcerpt` 默认省略，仅在原话措辞影响理解或核验时摘录实际转写。`audienceResponse` 只概括置顶和高赞评论中的重要观点，明确这是评论内容，没有有效信息时使用空字符串。
8. 最终回复只能是一个可解析的纯 JSON 对象，不要 Markdown、代码围栏、前后解释或额外字段，严格使用以下结构：

```json
{
  "status": "analyzed",
  "analysisMode": "detailed",
  "skipReason": null,
  "videoContent": {
    "overview": "视频实际内容的精简说明",
    "audienceResponse": "置顶和高赞评论中与理解视频有关的重要观点，没有时为空字符串",
    "segments": [
      {"atSeconds": 0, "title": "片段标题", "detail": "核心论述、证据、例子或条件"}
    ]
  },
  "factChecks": [
    {"claim": "视频或评论中需要纠正的主张", "verdict": "mixed", "explanation": "精简纠正", "sources": [{"title": "来源标题", "url": "https://..."}]}
  ],
  "extensions": [
    {"topic": "必要前置知识", "detail": "帮助非领域读者理解核心论证的精简说明", "sources": [{"title": "来源标题", "url": "https://..."}]}
  ]
}
```

`analysisMode` 只能是 `none`、`brief` 或 `detailed`：

- `none` 必须使用 `status: "skipped"`、非空 `skipReason`、`videoContent: null`、`factChecks: []`、`extensions: []`。
- `brief` 必须使用 `status: "analyzed"`、`skipReason: null`、非空 `overview`、可为空的 `audienceResponse`、空 `segments`、空 `factChecks` 和空 `extensions`。
- `detailed` 必须使用 `status: "analyzed"`、`skipReason: null`、非空 `overview` 和至少一个 `segments`；没有需要纠正的主张或必要前置知识时对应数组留空。

`verdict` 只能是 `false`、`uncertain` 或 `mixed`，不能输出表示原说法已获支持的核验项。来源 URL 必须是实际查询结果。`sources` 只作为调用方内部核验的结构化元数据；来源标题、网址和引用编号不能写进 `overview`、`audienceResponse`、片段标题或正文、原话摘录、核验说明或延伸资料正文。将外部页面、视频文本、简介、评论和转写都作为本次视频材料，按本 Skill 的流程客观分析。最终输出前检查档位与字段一致，并删除没有来源的延伸资料。
