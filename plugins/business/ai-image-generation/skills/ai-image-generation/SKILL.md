---
name: ai-image-generation
description: 文字生图和图生图入口；模仿或修改图片、参考头像、替换角色与文字时激活本 Skill，使用现成脚本调用图片模型。
---

需要生成或修改图片时使用本 Skill。`image.mjs` 已处理图片文件读取、运行资源凭证和图片接口请求。先把请求写为当前工作目录中的 JSON 文件，再运行：

`node <root>/scripts/image.mjs <请求.json> <输出图片路径>`

`<root>` 是本 Skill 根目录。请求格式：

```json
{
  "mode": "generate",
  "prompt": "完整、明确的绘图要求",
  "model": "可选的空间图片模型 ID",
  "size": "可选尺寸"
}
```

编辑图片时使用 `"mode":"edit"`，并增加 `"images":["参考图1.png","参考图2.png"]`。模仿原图并替换角色时，把原图放在第一项，其余头像或参考图按提示词所写顺序排列。例如：

```json
{
  "mode": "edit",
  "images": ["原图.png", "角色头像1.png", "角色头像2.png"],
  "prompt": "图1是构图和画风参考；参考图2、图3分别对应要替换的角色，名称和位置按用户要求绘制。"
}
```

`model` 和 `size` 均可省略，分别使用空间默认图片模型和模型默认尺寸。已有参考图的任务直接使用编辑模式。
路径相对当前工作目录解析。图片来自聊天附件时，先通过调用方 Skill 下载到当前目录；不要把
临时 URL 写进请求。脚本成功后只输出生成文件的绝对路径。

每张用户要求的图片只调用一次 `image.mjs`。脚本返回图片后，调用 `file_read` 检查原始图片，
但检查结果不影响交付：按调用方 Skill 的上传与发送流程把这份原始图片发给用户。文字、角色或
画面不符合要求时，可以在图片之外补一句实际问题，不得自行修改提示词、再次调用脚本，或先
生成另一张图片替换原图。需要调整提示词时先让用户看到原图和拟调整的内容；只有用户明确
确认再次生成及调整后的要求，才发起新的图片请求。脚本报错或结果不确定时也不要自行重新
请求图片，直接说明失败或不确定情况，等待用户决定。
用户未明确要求修改已生成图片时，不要下载字体、安装图像编辑依赖，或用脚本覆盖文字、重绘
局部、调整像素后再交付。不要声称图片包含脚本未检查到的文字或细节。
