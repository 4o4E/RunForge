本 Skill 处理已经取得的各来源音视频文件。分析目标、处理范围、详细程度及最终回复格式由空间与本次可信任务提示词决定；按当前问题选择需要的音轨、转写或画面，不要求所有任务执行同一套步骤。

## 取得输入文件

- QQ 原生视频、语音及转发记录中的附件：使用当前空间的 QQ 能力按真实消息键和附件序号物化附件，再下载到会话工作目录。不要把附件元数据当成已读取的媒体内容。
- B 站 URL：使用可用的 `business:bilibili-video-analysis/video-analysis` 获取对应分 P 的媒体。
- 其他平台：通过该平台的可用能力取得媒体；已有可访问的媒体直链时下载原文件。网页 URL 不等于媒体直链，没有可用获取方式时明确说明限制，不根据标题臆测视频。
- 已经下载到会话工作目录的文件：直接复用，不重复下载或转换来源平台。

## 读取媒体

当前运行环境只支持 Linux amd64。使用 `ffprobe` 获取媒体格式、编码、时长和流信息，使用 `ffmpeg` 完成音频提取和必要的转码。以下 `<root>` 是激活结果提供的本 Skill 根目录：

- 媒体信息：`ffprobe -v error -show_format -show_streams -of json <媒体路径>`，先确认实际时长和音视频流，不能只根据文件扩展名判断。
- 语音转写：`node <root>/scripts/transcribe.mjs <媒体路径> <输出.srt> [语言]`，语言默认 `zh`。输入可以是包含音轨的视频或独立音频，脚本会提取音频并压缩后交给 Speaches，输出标准 SRT；读取实际转写后再回答讲话内容。没有音轨时不调用转写；空转写只表示没有识别到有效讲话。
- 均匀抽帧或指定时间抽帧：`node <root>/scripts/frames.mjs <视频路径> <输出目录> [秒数CSV]`。脚本输出 `frames.json`，其中包含每张图片的秒数和路径。

需要理解视觉内容时读取抽取的真实图片，使用支持图片输入的模型，不把抽帧清单当成已看过画面。无音轨或空转写不妨碍视觉分析；只询问画面的问题不必先转写，只有讲话证据的问题也不必抽帧。音轨、画面及外部资料的结论分别说明，缺失的证据如实保留不确定性。

输入文件、中间文件和结果必须写入当前会话工作目录；不要下载或安装其他版本的媒体工具。
