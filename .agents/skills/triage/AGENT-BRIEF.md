# 工作说明

Agent Brief 是工作项进入 `ready-for-agent` 时发布的执行说明，用来指明本次范围、依赖与验收来源。OpenSpec 继续作为需求、设计决定和任务的权威来源，工作项评论不维护第二份规格。

## 准备条件

1. 读取完整工作项讨论、对应 OpenSpec change、主规格、design 和 tasks。
2. 核对用户已经确认的范围、实际实现与未决事项。业务、架构或数据库选择尚未决定时，不标记为可实施。
3. 指明本次任务与其他工作项的依赖，以及可以独立运行的验证入口。

## 写入内容

- 用具体用户场景说明工作目的，不复制完整规格或实现步骤。
- 必须引用 change 路径、相关规格主题与需求名称、设计决定位置及任务编号；可附与当前版本绑定的源码定位作为调查线索，不将行号当作永久契约。
- 验收围绕该工作项覆盖的可观察行为与边界，并引用 OpenSpec 中对应场景。新增验收条件先更新 OpenSpec，再在工作说明中引用。
- 明确非目标与授权边界；工作项不能额外授权提交、推送、部署或修改共享环境。
- PR 的说明面向当前差异中尚待完成的内容，不假设要从头实现整个需求。

## 工作说明模板

```markdown
## Agent Brief

**工作内容：** 用户需要完成的具体场景与本工作项范围。

**OpenSpec 来源：**
- 变更：`openspec/changes/<change>/`
- 规格：相关主题、Requirement 与 Scenario 名称。
- 设计：该变更的 `design.md`，相关已确认决定。
- 任务：`tasks.md` 中本工作项负责的编号。

**当前证据：** 已读取的实现、实际运行结果与仍然未知的内容。

**依赖：** 阻止当前工作开始的工作项，或明确说明无依赖。

**验收：** 引用对应场景，说明实际运行入口和成功条件。

**不在范围内：** 相邻但未经批准的功能、资源与操作。
```

完成标准：后续开发助手能够从工作说明直接找到同一套 OpenSpec、负责范围与验收条件，没有在评论中建立另一个需求或架构决定来源。
