# bwrap 沙箱实施记录

RunForge 的所有 Linux Shell 子进程都通过 bwrap 保护只读资源，后端缺失或不可用时明确失败。后台可以选择容器范围访问或完整会话隔离。

完整会话隔离只给当前会话工作区写权限；当前用户目录由空间授权决定是否挂载，其他会话与用户目录不可见，网络按系统设置隔离或共享。容器范围保留原文件与网络范围；两种方式都只读绑定托管资源和插件快照的逻辑入口与真实目标。Skill 与 SDK 的物化副本保留原有文件权限，源文件、插件哈希和历史锁不变。完整边界见 [工具沙箱设计](../tool-sandbox.md)。

命令来源是运行容器的 PATH，不再维护逐个命令的白名单。管理员配置的危险命令正则在工具入口拦截明显误操作；文件和网络边界由 bwrap、容器及文件工具路径检查承担。

bwrap 自身和实际 Shell 都显式传入受控环境，防止通过 PID 1 的初始环境读取后端秘密。托管启动前失败会保存失败原因、结束命令并释放会话，修复运行环境后能够在同一会话重新执行；异常收尾只释放仍处于 busy 状态的会话。

本地真实容器验收覆盖常用文件命令、`jq`、`ffmpeg`、`uv`、`pnpm`，以及其他用户目录和 WSL 宿主路径不可见。服务端测试覆盖自定义 PATH、用户目录隔离、只读托管资源和插件快照。
