# 前端路由化实施记录

## 背景

原逻辑虽然能从 `/chat/:threadId` 恢复会话，但 URL 没有空间信息，无法区分同一租户下的
空间，也无法让 external 空间进入统一 Web 入口。

## 本阶段变更

- 轻量路由工具将空间和会话映射为稳定地址：
  - `/{spaceId}` 表示指定空间的入口或新会话页。
  - `/{spaceId}/{threadId}` 表示该空间下的指定会话。
  - `spaceId` 使用 `sp_` 前缀，`threadId` 使用 `th_` 前缀，因此不需要 `/s`、`/chat` 等资源名单前缀。
  - 旧 `/chat/{threadId}` 只作为兼容输入，加载后重定向到 default 空间的新地址。
  - `?draft=...` 保存未发送的文本草稿，属于 query param（查询参数）。
- 搜索仍属于当前空间，通过 `/{spaceId}?view=search&q=...` 表达，不引入第三段动态路径。
- `App` 改为从 URL 读取当前会话，并监听浏览器前进/后退。
- 选择空间、选择会话、新建会话、首次发送后端创建会话时，都会同步更新 URL。
- 刷新会话地址时，后端同时校验 URL 中的空间和会话归属；两者不匹配按不存在处理。
- Web 空间只列出当前用户自己的会话；external 空间按空间可见名单列出外部会话并只读展示。
- external 活动 run 每 2 秒从持久化详情刷新，不复用仅允许执行用户订阅的 WebSocket。
- external 页面隐藏 Composer、回答、继续、取消、分支、重命名、归档、删除、文件编辑和 Web shell。
- 附件不放入 URL，因为浏览器出于安全原因不允许恢复本地文件选择。

## 原因

路由只承载“定位信息”和轻量 UI 状态，消息内容仍使用后端持久化历史。这样地址可以分享、
刷新可以恢复，也不会把长对话内容塞进 URL。

## 权限边界

- 空间可见不等于可以读取其他用户的 Web 会话；Web 会话继续按 `tenant + user` 隔离。
- external 查看者先通过空间可见性校验，再用会话真实执行身份读取既有数据；该内部读取身份不进入任何写接口。
- URL 中的 `spaceId` 是公开业务 ID，不承担鉴权；权限仍由登录身份、空间名单和后端查询条件共同保证。
