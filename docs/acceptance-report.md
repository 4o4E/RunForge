# 能力与验收边界

本文说明当前源码的能力范围与验收入口，不声明某个运行实例已经部署，也不替代一次具体发布的测试报告。行为要求见 [OpenSpec](../openspec/README.md)，实现解释见[系统设计](system-design.md)。

## 当前能力

| 使用场景 | 当前实现 | 约束与说明 |
| --- | --- | --- |
| 用户登录与租户管理 | 租户账号、JWT/refresh token、用户 API token、独立系统管理员入口、角色与审计权限 | 系统资源由系统管理员维护，租户只使用获准资源；系统管理员审查内容走独立入口 |
| 配置任务运行环境 | Web/external 空间、可见成员、模型、提示词、Skill/MCP、业务插件 | 每次运行保存有效配置副本；后续空间修改影响新运行，不改写已有运行 |
| 多步任务与长对话 | thread/run/step、计划、工具执行、上下文压缩、取消与重启恢复 | 单个活动服务实例，不是分布式队列或跨 worker 接管 |
| 模型协议 | OpenAI Responses、OpenAI Chat Completions、Anthropic Messages，统一流式调用与 ProviderRunner 观测 | 模型能力使用管理员保存的配置；已经发布流式输出的失败请求不会自动重试 |
| 执行命令 | 普通 Shell、托管 Shell session、前台与后台命令、命令日志和终止 | Linux 始终要求 bwrap；容器范围与完整会话隔离具有不同可见范围 |
| 文件和附件 | 受控会话目录、用户跨会话文件、上传下载、分享签名和多模态读取 | 文件工具、Web 文件接口与 Shell 分别执行各自的真实路径和授权边界 |
| 扩展业务 | 内置 Skill、业务插件 Skill/MCP、运行资源 SDK、tenant Secret 与数据源短期凭证 | 业务插件是声明式资源，不装入服务端任意代码；新运行锁定插件内容快照 |
| 异步协作 | `subagent_run` 按 runtime profile 与主任务授权派发子任务，保存输出与用量；readonly 提供只读工具，writer 可使用读写与 Shell | 与主任务共享会话工作区，不具备独立沙箱、跨进程恢复或资源配额 |
| 外部应用接入 | external 空间、调用方 Token、运行创建/追加/查询/取消、产物上传与读取 | Web 内容与执行只读；租户 owner/admin 可以管理共享对话元信息及生命周期 |
| 历史与用量 | step 聚合、运行元数据、请求快照、Provider attempt、按运行的本地 trace、Token 与存储分析 | 请求快照仅用于管理员观测；历史与恢复不依赖 trace；用量统计不是计费系统 |
| Web 控制台 | 实时输出、计划、文件/Shell/子任务资源面板、Markdown/Mermaid/LaTeX 与 HTML 文件预览 | 真实页面与真实模型交互需要独立验收，不能由单元测试成功替代 |

## 数据与上下文不变式

- `steps.result` 保存完整模型响应，`steps.tool_results` 保存工具结果；`messages` 保存输入、摘要与顺序索引。
- 压缩只派生模型视图，不覆盖 step 原文；压缩选择保存在 `runs.metadata.context.collapsed`。
- 工具调用与结果始终配对。恢复中断执行时明确记录中断，不把未执行动作记为成功。
- L1 遮蔽、L3 摘要与 L2 内存窗口分别处理上下文；窗口裁剪不会删除持久化历史。
- Skill/MCP/按需工具的激活属于当前运行。恢复同一运行读取运行元数据，新运行重新激活。
- trace 保存原始流式与诊断记录，默认保留三十个自然日；它不是对话权威正文，也不是恢复来源。

## 尚未实现的能力

- 多 worker 调度、分布式运行租约、心跳、抢占与跨实例接管。
- 每次运行独立工作区，以及 CPU、内存、进程数、磁盘配额和网络域名名单。
- 子任务独立沙箱和跨 worker 恢复。
- 托管 Shell 的远程 worker 后端和完整交互式 PTY/stdin 控制。
- 独立远程 Skill 安装、签名验证与每个 Skill 的资源配额。
- 跨会话 Gene Memory、经验检索与经验更新闭环；[相关文档](subagent-memory-design.md)中的这些内容属于设计，不是已实现功能。
- 计费、套餐与统一 resource URL 权限模型。已有 Token/存储统计及租户身份权限不属于这些未实现事项。

## 验证入口

具体命令、依赖和覆盖范围统一维护在 [CI 与真实验收分层](testing/ci-and-verification.md)：

1. 类型检查、构建与单元测试验证对应包的实现。
2. 专用 PostgreSQL 数据库验证真实迁移、Store、HTTP、历史与关闭行为。
3. 真实模型与浏览器验证供应商连通性、长任务压缩和实际用户操作路径；需要独立环境及费用授权。
4. 发布流水线另外验证自带与外部 PostgreSQL 的两种容器部署，以及发布镜像拉取。

交付记录只填写实际执行的项目及其结果；尚未执行的项目明确保留为未验收。历史实施记录见 [impl-log](impl-log/)，不把历史证据自动视为当前版本验收。
