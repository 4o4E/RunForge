# 工具沙箱

RunForge 在共享的 Linux 运行容器中启动服务。每次 Shell 命令由 `bwrap` 建立独立的文件、进程和可选网络视图；容器负责提供通用命令，`bwrap` 负责限制命令能够访问的数据。管理员可以选择不使用 `bwrap`，但这会同时失去会话文件隔离。

## 文件边界

- 当前会话的 `/w/<spaceId>/c/<threadId>` 可写；同空间的其他会话目录不挂载。
- 当前执行用户的 `/u/<userId>` 仅在空间规则允许时可写；其他用户目录不挂载。
- 本次运行选中的 Skill、Workflow、SDK 和业务插件快照只读挂载；未选中的版本不挂载。
- `/tmp` 和沙箱根目录使用临时文件系统，不能保存跨命令需要保留的数据。
- 服务进程内执行的文件工具不经过 `bwrap`，按同一会话和用户根目录进行真实路径检查。

容器的 seccomp 和可选 AppArmor 配置允许 `bwrap` 创建嵌套 namespace。部署要求见 [`deploy/security/README.md`](../deploy/security/README.md)。运行镜像以非 root 用户运行；本地 Compose 还丢弃了全部 capability。

## 命令和 PATH

容器运行镜像安装常用文件、网络、开发和媒体命令。Shell 在 `bwrap` 中按系统或管理员指定的 PATH 查找命令；系统可执行目录和 PATH 指向的其他目录只读挂载。RunForge 在生成挂载参数前检查 PATH 目录的真实路径，拒绝容器根目录以及会暴露其他会话或用户目录的路径。当前会话工作目录和获准的用户目录由独立挂载提供，业务插件声明的命令入口排在 PATH 最前面。

不再逐个选择可见命令。`shellDeny` 是由管理员维护的正则规则，用于拦截明显危险的命令文本，属于防误操作机制；解释器、脚本和复杂 Shell 语法可以表达等效操作，不能把命令黑名单当作安全隔离。真正的数据边界由容器权限、`bwrap` 挂载和文件工具路径检查提供。

Shell 默认不继承服务端密钥。数据库访问需要正式的 workload token；直接数据库 CLI 仍由工具层阻止。工具输出继续进行脱敏和长度限制。

## 网络与执行方式

- `TOOL_SANDBOX=enforce` 且后端为 `bwrap` 时，默认隔离网络；系统设置允许网络时，命令共享容器网络。
- `TOOL_SANDBOX_BACKEND=bwrap` 强制使用 `bwrap`，不可用就失败；`auto` 在不可用时回到容器内直接执行并告警。
- `shellUseHostPath=true` 让命令直接在 RunForge 容器中执行，使用同一 PATH，但不再具备会话文件隔离。用户文件目录只允许映射进 `bwrap`，不能在此模式下使用。
- 前台 `shell` 和托管 Shell 使用同一套策略。后台进程仍由托管 Shell 管理生命周期和日志。

更改运行镜像或 PATH 后，应在真实容器里验证常用命令、当前会话与用户文件可写、其他会话及用户文件不可见、禁用网络时不能联网，并检查服务日志显示预期的沙箱后端。
