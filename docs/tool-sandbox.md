# 工具沙箱

RunForge 在共享的 Linux 运行容器中启动服务。所有 Linux Shell 命令都通过 `bwrap` 执行，插件、Skill 和 SDK 的逻辑入口与真实目标始终只读。管理员可以选择容器范围访问或完整会话隔离；选择范围不会关闭资源保护。

## 文件边界

以下可见性边界适用于完整会话隔离；容器范围访问保留容器原有文件范围，但当前会话和空间的托管资源仍只读。

- 当前会话的 `/w/<spaceId>/c/<threadId>` 可写；同空间的其他会话目录不挂载。
- 当前执行用户的 `/u/<userId>` 仅在空间规则允许时可写；其他用户目录不挂载。
- 本次运行选中的 Skill、SDK 和业务插件快照只读挂载；未选中的版本不挂载。
- `/tmp` 和沙箱根目录使用临时文件系统，不能保存跨命令需要保留的数据。
- 服务进程内执行的文件工具不经过 `bwrap`，按同一会话和用户根目录进行真实路径检查。

容器的 seccomp 和可选 AppArmor 配置允许 `bwrap` 创建嵌套 namespace。部署要求见 [`deploy/security/README.md`](../deploy/security/README.md)。运行镜像以非 root 用户运行；本地 Compose 还丢弃了全部 capability。

物化资源保留原有文件权限和脚本执行位，Shell 的资源只读限制由 bwrap 挂载提供。服务端直接清理实体目录或入口链接，不跟随链接删除源文件。插件源码和不可变快照的权限、内容哈希及历史运行锁保持不变。

## 命令和 PATH

容器运行镜像安装常用文件、网络、开发和媒体命令。Shell 在 `bwrap` 中按系统或管理员指定的 PATH 查找命令；完整会话隔离下，系统可执行目录和 PATH 指向的其他目录只读挂载。RunForge 检查这些目录的真实路径，拒绝容器根目录以及会暴露其他会话或用户目录的路径。当前会话工作目录和获准的用户目录由独立挂载提供，业务插件声明的命令入口排在 PATH 最前面。

不再逐个选择可见命令。`shellDeny` 是由管理员维护的正则规则，用于拦截明显危险的命令文本，属于防误操作机制；解释器、脚本和复杂 Shell 语法可以表达等效操作，不能把命令黑名单当作安全隔离。真正的数据边界由容器权限、`bwrap` 挂载和文件工具路径检查提供。

Shell 默认不继承服务端密钥。数据库访问需要正式的 workload token；直接数据库 CLI 仍由工具层阻止。工具输出继续进行脱敏和长度限制。

完整隔离只投射系统目录和明确配置的 PATH 目录。安装在系统目录之外的 Node、pnpm 等工具，其启动脚本或符号链接可能依赖相邻目录；这些运行目录也需要通过 `SHELL_PATH` 明确配置。CI 显式提供 Node 安装根目录和 pnpm 的 `node_modules` 目录，不自动扩大到用户主目录或其他父目录。

## 网络与执行方式

- 所有 Linux 执行范围都要求可用的 `bwrap`；缺失或无法创建 namespace 时明确失败，不直接执行 Shell。
- `shellUseHostPath=false` 且后端为 `auto` 或 `bwrap` 时启用完整会话隔离；两种配置采用同一用户目录授权条件。网络默认隔离，系统设置允许网络时共享容器网络。
- `shellUseHostPath=true` 或后端为 `none` 时使用容器范围访问，保留容器原有文件与网络范围，仍保持资源只读。
- `TOOL_SANDBOX=off/enforce` 只控制附加工具策略，不参与 Shell 范围选择。后台独立保存这两项设置；网络开关控制完整隔离的 Shell，并在启用工具策略时控制 Web 工具。
- 前台 `shell` 和托管 Shell 使用同一套策略。后台进程仍由托管 Shell 管理生命周期和日志。
- bwrap 管理进程和实际 Shell 均显式使用受控环境，不继承后端数据库连接或 API key；PID 1 的初始环境同样不能暴露这些值。
- bwrap 启动前失败时，命令持久化为失败并释放会话；修复环境后可以继续使用同一会话，不回退到直接执行。

更改运行镜像或 PATH 后，应在真实容器验证常用命令、两种访问范围的资源只读和正常工作区写入，以及完整会话隔离下其他会话与用户目录不可见、网络开关生效，并检查服务日志显示预期访问范围。

## 包管理镜像源

系统管理员在 `/sys-admin/settings/tools-sandbox` 设置 Python 和 Node 镜像源。默认分别为 `https://pypi.tuna.tsinghua.edu.cn/simple` 和 `https://registry.npmmirror.com/`；空白恢复实例默认值。

容器提供同样的默认值。每次新 Shell 命令从系统设置读取最新值，分别注入 `PIP_INDEX_URL`、`UV_DEFAULT_INDEX`、`NPM_CONFIG_REGISTRY` 和 `PNPM_CONFIG_REGISTRY`。保存后无需重建会话或重启服务；已经启动的安装进程保持原环境。显式命令参数、作用域 registry 和锁文件中的下载地址仍遵循包管理器自身规则，不关闭 TLS。

## 图片与多模态输入

图片进入模型前，在本地读取真实内容和尺寸：任一边不超过 8000 像素，总像素不超过 2400 万，最终输入不超过 10 MiB。超限错误包含实际尺寸和限制，要求裁剪或缩放；长图优先按顺序分段裁剪。系统不自动缩小或丢弃原图内容。

主任务和子任务均使用统一图片规则：使用已有图片工具在工作区另存副本，再通过 `file_read` 交给支持图片的多模态模型分析，不安装或使用 OCR 替代。图片未进入模型时不得声称看见内容。只有上游明确否定模型的图片能力，才判定模型不支持图片；格式、尺寸或泛化输入错误不能禁用后续正常图片。
