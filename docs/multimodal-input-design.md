# 多模态文件输入

RunForge 的对话模型请求与工作区文件读取是两条独立路径。用户附件先作为受控文件保存在当前会话；消息保留原始附件标记，并记录文件类型与路径。模型请求只为本轮需要读取的图片装载字节。历史图片保留引用，需要再次查看时由 `file_read` 读取。

## 模型直接输入

- 发送图片前根据文件实际内容解码并识别格式。静态 PNG、JPEG、WebP 直接发送；其他可解码的静态图片转换为 PNG。动态图像不按静态图片发送，应由 `file_read` 按时间读取画面。
- 配置的模型不支持图片时，本轮只发送文字及“图片未进入模型”的明确说明。模型可以继续处理文字，但不能声称看过图片。
- 上游明确返回图片输入不受支持，且尚未输出正文、推理或工具调用时，本轮最多重试一次纯文本请求。仅在明确的图片拒绝错误上执行该操作；其他错误保持原状。本次运行记住拒绝该图片类型的模型，避免后续工具读取重复触发相同错误。
- 被模型消费过的用户图片不在后续请求重复装载。原始消息和文件引用继续保留，便于用户追问时重新读取。

## 统一文件读取

`file_read` 保持单一工具入口，按文件真实类型选择处理器；文本、图片、PDF、Office 文档、音频、视频分别使用适合的读取方法。`mode=metadata` 返回规模和可读取范围；`pages` 指定文档页面；`timeRange` 指定视频或动态图像的区间；`maxFrames` 控制画面数量。

网页上传直接发送 multipart 文件流，服务端检查目标路径权限后写入同目录临时文件，完整接收才替换目标文件。单文件上限为 1 GiB；请求中断或超限时清理临时文件。旧 JSON 上传调用继续可用。

- PDF 提取文字，并只把指定页面渲染成图片。Office 文档复用现有的 PDF 预览转换服务，再走 PDF 读取流程。页面图像仍受模型图片能力与预算限制。
- 音频通过 OpenAI 兼容转写端点读取语音；当前空间选中 `audio-video-tools` 业务插件时沿用该插件的租户 Speaches 配置和 Secret 审计，否则使用平台转写配置。长录音按服务单文件限制分段，并保留原文件时间戳。转写文本不代表音乐或环境声音的全部内容。
- 视频使用 `ffprobe` 获取时长与轨道信息，用 `ffmpeg` 按请求区间提取带时间戳的画面，并转写相同区间的音轨。抽样画面和转写文本必须标明实际覆盖范围，不能当作整段视频的完整内容。
- 工具产生的页面和画面保存到当前会话的受控目录，工具结果只保存媒体引用。模型请求时才读取图片；同一轮所有工具结果保持连续。

## 存储、预算与观测

`messages.content` 始终保留原始内容。`messages.media_refs` 只保存受控文件路径、类型和名称；媒体字节不写入这一列。步骤快照、模型请求与响应记录、本地追踪记录会省略媒体字节，同时保留调试需要的消息结构、媒体类型和大小。旧派生观测记录通过追加迁移与追踪文件清理命令处理，不修改原始对话消息。

上下文估算按中文、英文分别保守计算，并计入工具定义与本轮尚未消费的图片引用；真实模型用量仍由供应商返回值记录。旧历史压缩后仍超预算时，将最近完整工具调用及全部结果一起生成分段摘要，原始消息和调用结果配对不变。读取工具限制单次页面、画面和文字数量，并在输出中说明截断或抽样范围。文字与媒体的数量限制是输入预算的保护，不能用来声称已分析被省略的文件部分。
